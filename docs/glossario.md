# Glossário

Use o termo técnico quando ele ajuda a pesquisar ou conversar com a área. Na leitura inicial, estas definições explicam o significado usado pelo guia.

| Termo | Significado neste processo |
| --- | --- |
| Briefing | Visão resumida de problema, público, proposta, objetivo e escopo |
| Descoberta — discovery | Trabalho para entender problema, contexto e necessidades; pode aproveitar pesquisas existentes |
| Fonte oficial | Local indicado pelo projeto para uma decisão ou informação vigente, com responsável e versão |
| Base aprovada — baseline | Conjunto de decisões e materiais aprovados para um escopo e versão identificados |
| UX | Experiência de uso: necessidades, jornadas, comportamentos e recuperação de erros |
| UI | Interface: elementos, hierarquia visual, componentes e estados |
| Sistema visual — design system | Padrões de aparência e componentes que materializam decisões de interface |
| Requisito de qualidade | Propriedade verificável, como tempo de resposta, disponibilidade, acessibilidade ou segurança |
| Arquitetura | Estrutura e limites da solução e as decisões que os justificam |
| ADR | Registro de uma decisão arquitetural, com contexto, alternativas e consequências |
| Conjunto de tecnologias — stack | Linguagens, frameworks, bibliotecas e ambientes de execução selecionados |
| Ferramentas de desenvolvimento — toolchain | Ferramentas usadas para instalar, construir, analisar, testar e entregar o software |
| Ambiente de execução — runtime | Contexto tecnológico em que o código é executado |
| Limite — boundary | Separação entre módulos, sistemas, responsabilidades ou áreas de confiança |
| Backlog | Fila ordenada de trabalho; neste guia, sua fonte principal são Issues |
| Issue | Registro de uma tarefa, pesquisa, bug, proposta ou objetivo no GitHub |
| PR — pull request | Mudança proposta para revisão e integração em uma branch |
| Fundação — setup | Preparação técnica necessária para desenvolver e operar a solução |
| Iteração | Ciclo de trabalho com prazo definido; o guia também permite fluxo contínuo |
| Incremento funcional | Capacidade acrescentada ao produto e verificável no seu escopo |
| Incremento vertical | Capacidade de ponta a ponta, atravessando as camadas necessárias da solução |
| Transferência de contexto — handoff | Passagem de objetivo, fontes, decisões, evidências, pendências e responsabilidade |
| Critérios de conclusão — Definition of Done | Condições verificáveis para concluir um tipo de trabalho |
| QA — verificação da qualidade | Atividades para conferir requisitos e comportamento, registrando condições, resultados e evidências |
| Verificação obrigatória — quality gate | Critério que deve ser atendido antes de avançar ou liberar |
| Pré-produção — staging | Ambiente usado para conferir o candidato em condições representativas, com limites declarados |
| Liberação ou promoção | Passagem da versão validada para o próximo ambiente autorizado |
| Retorno de versão — rollback | Retorno a uma versão anterior; alterações de dados podem exigir recuperação adicional |
| Guia operacional — runbook | Instruções para executar uma rotina ou responder a um incidente |
| Habilidade — skill | Instruções e recursos reutilizáveis de uma ferramenta de IA, cuja disponibilidade deve ser confirmada |
| Agente | Ferramenta de IA que executa uma responsabilidade com capacidades e limites definidos |
| Registro de continuidade — checkpoint | Estado persistido para outra pessoa ou ferramenta retomar o trabalho |
| Evidência | Fonte ou resultado observável que sustenta uma afirmação dentro de condições e limites |
| Inferência | Conclusão derivada de informações, que precisa ser distinguida do que foi diretamente observado |
| Estimativa | Projeção dependente de premissas; não equivale a medição ou custo realizado |
| Comparação de referências — benchmarking | Análise estruturada de alternativas e práticas para adaptar ao contexto |
| Benchmark de desempenho | Medição com condições declaradas; números públicos de outro ambiente não são medições do projeto |

Uma semana de trabalho é um ciclo. Permitir cadastrar e consultar um endereço é uma entrega funcional. Esse resultado pode exigir formulário, validação e persistência. Não confundir período com resultado nem incremento vertical com uma arquitetura específica.
